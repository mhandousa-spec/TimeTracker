## 5. Firebase / data model

- **New collection:** `Modules/time_tracker/Counters/{series}` with field `Last_Number` (decision 50).
  - Series: `REQ-2026`, `TRX-2026`, `LOC`, `GRP`, `RQT`, `CMT__{requestId}`.
  - **Amr must allow company users to read and write `Counters` in the security rules**, like the other Time Tracker collections. Without that, creating a request, location, group, type or comment fails.
- **New document-ID format, for new documents only.**
  - Format: `REQ-2026-0001`, `TRX-2026-0001`, `LOC-0001`, `GRP-0001`, `RQT-0001`, `CMT-0001` (per request).
  - The ID is allocated in the same transaction as the write, and an ID that already exists is skipped. Existing records keep their IDs.
  - `TODO-0001` (listed in decision 48) is **not** implemented; the Todo module is outside Time Tracker.
- **Approve justification** is stored in the existing approval-step `Reason` field. No new field.
- No other new fields or collections. Multi-location (`allowedLocationIds`) and the assignment history use fields that already existed.
- **No data was written or migrated by this session.**
  - All tests use in-memory fakes.
  - No migration script was written or run; the readable-ID rename of old records was never started.
  - The only writes come from Moataz using the app, including the debug-only "demo data" button.
